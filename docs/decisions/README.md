## ADR 模板（新建决策复制此骨架）

```markdown
# ADR-NNN：<一句话标题>

- **编号**：NNN
- **日期**：YYYY-MM-DD
- **状态**：提议中 / 已采纳 / 已废弃（被 ADR-XXX 取代）
- **关联**：docs/requirements/Px-y-xxx.md（如有）

## 背景
<遇到什么问题，为什么现有做法不够>

## 决策
<决定了什么，关键结构/签名/配置用代码块给出>

## 理由
<为什么选这个方案，核心权衡是什么>

## 影响
<正面收益 + 需要注意的代价/边界，后续迁移点>
```

## 写与不写的边界

**写 ADR（非显而易见的架构决策）**：
- 有多种合理方案、做了取舍的（如 has/ensure 拆分、ServiceError 分层设计）
- 改变系统结构或模块间契约的（如引入 service 层、LLM 网关统一）
- 未来回看会问"当时为什么这么干"的（如 NULL 归属语义、404 防枚举）

**不写 ADR（常规需求实现）**：
- 加字段、加接口、加索引、加普通 CRUD
- bug 修复（记 changelog + 重难点文档即可）
- 参数调优、文案修改、样式调整
