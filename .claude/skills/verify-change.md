# Skill：改动验证清单（verify-change）

> 每轮改动收尾时对照执行，验收结果（命令 + 实际输出结论）写入 changelog。按改动类型选取适用小节，鉴权/归属改动必须全跑。

## 1. 功能场景

- [ ] 核心路径 curl 实测（注册/登录 → 拿 token → 正常调用 → 预期响应）
- [ ] Swagger `/docs` 锁图标符合预期（业务端点全部锁定）
- [ ] 前端走一遍核心流程（`npx tsc -b` 通过 + 浏览器操作）

## 2. 回归场景（基线回归，防改 A 坏 B）

- [ ] 无 token 访问业务接口 → 全部 401
- [ ] 普通用户写他人资源 → 403；读他人私有资源 → 404
- [ ] 他人会话访问 → 404（防枚举语义未破坏）
- [ ] 存量数据可见性不变（登录现有账号，知识库/会话数量与改造前一致）
- [ ] `/api/health` 200，`from app.main import app` 可加载全部路由

## 3. 边界场景

- [ ] 空库/空列表（新用户首次进入）
- [ ] user_id 为 NULL 的存量行（公共可读语义未破坏）
- [ ] 非法参数（不存在的 kb_id、超长字符串、错误类型）
- [ ] 分页/排序参数极值

## 4. 权限场景（矩阵全跑）

| 角色 | 读私有库 | 读公共库 | 写自己库 | 写他人库 | 管理接口 |
|---|---|---|---|---|---|
| 匿名 | 401 | 401 | 401 | 401 | 401 |
| 普通用户（无归属） | 403 | 200 | — | 403 | 403 |
| owner | 200 | 200 | 200 | 403 | 403 |
| admin | 200 | 200 | 200 | 200 | 200 |

## 5. RAG 链路专项（仅当触碰禁区文件或检索相关代码）

- [ ] `python3 scripts/run_ragas_eval.py` 指标与基线对比无恶化
- [ ] 语义缓存命中路径正常
- [ ] SSE 流式输出完整、引用溯源（CitationView）正常渲染

## 证据记录格式（写入 changelog 验收结果节）

```
<命令> → <关键输出摘录> → <结论 ✓/✗>
```

不接受"应该没问题"类结论；每项必须有实际执行证据。

判据写法约束（规则原文见 `docs/rules/90-workflow.md` 验证纪律）：写泄露/敏感/负面断言时，判据必须排除输入本身包含的词——断言词同时出现在输入 prompt 和输出回答中即无效，须换"只有读到真实数据才会出现的实体级词"或"输入中不存在但数据中存在"的对照词；负例选择须排除因其他机制（如 admin 豁免）而失效的对象，确保负例真正落在被验证的行为边界内。
